# CLI core (issue 37), 2026-10-05

**What worked**

- Keeping the layer in `cmd/` with pure pieces (selector grammar, remote parsing, table and TSV builders, jq wrapper, prompt helper with an injected reader and writer) made nearly everything unit-testable without a terminal. Only the TTY table output needed a pty test.
- `jaq` 3 (`jaq-core` 3.1, `jaq-std` 3.0, `jaq-json` 2.0) compiles on Rust 1.87 and the API is small: parse the serialised `serde_json` value with `jaq_json::read::parse_single`, compile once, iterate the outputs.

**Friction**

- Demo mode builds its XDG paths from a `MapEnv`, which hid `TERM`, `COLORTERM` and `NO_COLOR` from colour detection. The pty test caught it. `DemoProcessEnv` in `cmd/context.rs` now overlays only the `XDG_*` variables and passes everything else through.
- `--json` takes an optional value (so a bare `--json` can list fields), which means `review-buddy --json pr list` reads `pr` as the field list. Put `--json` after the command, or use `--json=fields`, as with `gh`.
