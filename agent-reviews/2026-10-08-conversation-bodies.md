# 2026-10-08: show the full comment bodies in the Conversation tab (#159)

**Worked:** the Detail body already had everything the new tab needed: `wrap_marked` and `plain_markdown` for the text, `extract::flatten` for the image notes, and the per-region text rows that the mouse selection work records during the draw. A comment is one region (`RegionKey::Comment`), so a drag stays inside one comment and wrapped rows rejoin. Giving the recorded rows an indent (`BodyText.indent`) kept the copied text free of the layout padding. Reusing the diff's `Intent` for the dashboard keys meant `c` and `⏎` needed no new screen: the diff opens, moves to the thread's line, and for a reply opens the composer with the existing `Target::Reply`.

**Friction:** the issue and SPEC say `c` replies and `⏎` jumps, but on the dashboard `c` opened a new comment and `⏎` only opened the diff, and there was no thread cursor at all, so the keys were added (`n` `N` `z` `Z`) and scoped to the Conversation tab with the Detail pane focused; from the Queue pane the old behaviour is untouched. `draw` computed the body three times a frame (once for `max_scroll`), so it now takes the scroll limit from the body it already built. The demo conversation was added to the "Tidy zsh startup" change (general threads only, one long, one short, beside the existing resolved one) rather than the menus change, because the menus change is selected in nearly every dashboard snapshot and its threads feed the diff snapshots and `pr view`; only one dashboard snapshot (the Conversation count, 2 to 5) and the four dashboard help snapshots (new rows) moved, and each was reviewed.

**Not verified:** a live GitHub or GitLab conversation (the work is on the shared model and the demo data); very long real threads on a slow terminal. The whole conversation is still laid out on every draw (folded threads are cheap, since they skip wrapping); there is no layout cache.
