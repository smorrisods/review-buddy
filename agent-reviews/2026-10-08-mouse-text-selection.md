# 2026-10-08: select and copy text with the mouse (#140)

**Worked:** recording each region's rows as logical text during the draw, next to the hit map, meant the copy never touches the buffer, so gutters, borders, padding and suggestion markers are excluded by construction rather than by trimming. Giving every wrapped row a join (`Break`, `Space` or `Glue`) at the point it is made (`wrap_marked` for prose, the wrap points for code) let one function rebuild a paragraph or a source line from its rows, which is also what makes triple-click and "soft-wrapped lines join" the same code. Positions are a row ordinal plus a cell column, never a screen position, so the wheel and edge scrolling during a drag cannot move them, and the selection keeps a copy of rows it has seen so text that scrolled out of view is still copied. One fingerprint of the screen (file, row counts, size, wrap, overlays, selected change) checked at the end of `update` replaced a dozen scattered "clear the selection" calls. The `#157` helpers (`ScreenMap`, `wrap_points`, `row_rects`) were all that was needed to get from a pointer to a row.

**Friction:** the plan said `BlockLine` needed a `cont` flag and that `Y` should use the source body through `Origin`. `Origin` only exists for editable blocks, so `Block` now carries the whole comment as written (`text`) for every block and `Y` reads that. A draw can only record the rows in view, but keyboard copy mode and edge scrolling need the neighbours of the last visible row, so while a diff selection exists the draw records 64 screen rows beyond the view (marked off screen, so they are never hit-tested). The existing range tests and the pty drag test pressed on the code column, which now starts a text selection, so they press on the gutter instead; the range snapshots did not change. The Selection role is a 12 percent tint of the accent, too close to the cursor line to tell apart, so the text highlight blends the accent more strongly into it (truecolour) and reverses cells otherwise; under `NO_COLOR` the cursor line is already reversed, so a selected cell there is flipped back and underlined. A first-use hint on every diff press replaced the footer hints at 100 columns and changed the range snapshots, so it shows on the first text press only.

**Not verified:** Windows Terminal and macOS drag, double and triple click, and OSC 52 behaviour (CI and the maintainer can check those); that `resume` after `⌃Z` keeps the live mouse state (the code reads the guard's own flag, but it needs a real tty to run); terminals that report only some mouse events during a drag.
