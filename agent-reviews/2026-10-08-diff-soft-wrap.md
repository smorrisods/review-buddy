# 2026-10-08: soft wrap in the diff (#136)

**Worked:** keeping `Rows`, the cursor, `RowRange` and every navigation function logical, and adding a separate `ScreenMap` (heights plus prefix sums) used only for scroll, reveal, draw and hit mapping, kept the change small: `step`, `nearest_line`, hunk jumps, ranges and `c` did not change at all. With wrap off the map is an empty identity, so the draw path and every existing snapshot stayed byte-identical (only the four diff help snapshots moved, by one help row). The wrap maths works from the raw line, so a tab's expansion is treated as one unit while the highlighted spans, which arrive already expanded, are sliced at cell offsets. A pure `hit_at` over the map gave the tests a way to check the draw against the mapping.

**Friction:** the plan listed `app/resize.rs` as a place to call the diff resize path, but that file only handles dashboard seams; the terminal pane's open, close and resize all pass through `terminal::after`, so one `diff::refit` there (compare the width the rows were built for with the current code width) covers every case. An early version registered a gutter rect and a code rect per row; that doubled the click targets and broke the existing "only visible rows register hits" bound, so the draw keeps one hit per screen row and `diffview::row_rects` and `hit_at` carry the gutter and code split for the mouse-selection follow-up. A 20,000-line test patch with long lines went over rb-diff's 1 MiB limit and silently fell back to the binary placeholder, which showed up as a screen map of zero rows.

**Not verified:** Windows and macOS rendering, and terminals that disagree with `unicode-width` about emoji sequences.
