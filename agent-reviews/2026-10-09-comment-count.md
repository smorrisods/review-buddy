# 2026-10-09: queue comment count includes thread comments, and a legend for the marks (#165)

**Worked:** the schema file GitHub publishes (`schema.docs.graphql`) settled what could be settled offline: `PullRequest.comments` is an `IssueCommentConnection` (general comments only) and `totalCommentsCount` is a nullable `Int` described only as "a count of how many comments this pull request has received". Both are consistent with the screenshot (a general count, or a null read as zero by `unwrap_or(0)`), so the fix doesn't depend on which it was: the list reads `comments { totalCount }` (an existing connection, so free) plus a `comments(first: 1) { totalCount }` under each of the first 50 threads. One shared definition (`rb_core::thread_comment_count`, `Signals::reconcile`) feeds the Conversation tab and the queue row, and the loaded threads replace the list's count for the selected row. The legend lives in `legend()` beside the key registry and is drawn as its own section of the help overlay with its own key column, because a 10-cell key column would have clipped the longest existing help labels.

**Friction:** the per-thread count is a connection under each thread under each change, which is the expensive shape for GitHub's rate-limit formula: about 29 points a page instead of about 4. The query-cost unit test now models nesting. The demo's `comments = 6` override on one change disagreed with its three threads, which the new shared definition exposed on the selected row (the count dropped to 3), so the override was removed and many snapshots moved from `¶6` to `¶3`; a script confirmed those were the only changed lines apart from the help overlay's row total. `pty_terminal` failed once under load and passed on rerun.

**Not verified:** real GitHub or GitLab responses (all fixtures are shaped from the documentation), whether `totalCommentsCount` was null or a general-only count in the screenshot, the GraphQL cost (calculated from the query, not read from a live `rateLimit`), and GitLab's `user_notes_count` excluding system notes (from GitLab's documentation and source as remembered, not observed).
